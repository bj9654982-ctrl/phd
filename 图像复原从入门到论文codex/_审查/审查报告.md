# `图像复原从入门到论文`审查报告

## 1. 结论

当前项目可作为阶段 01–03 的教学草稿，但还不能支撑“完成盲图像复原论文并投稿”的目标。Python 源文件均能通过语法编译；现有 9 组非盲反卷积测试中，维纳和 RL 的 PSNR 均高于模糊图基线，说明非盲反卷积主体具有可用性。主要问题集中在：核心阶段缺失、运动 PSF 参数实现错误、过渡区宽度定义与实现不一致、核心假设在现有数据上未复现、TV 方法名实不符、实验存在测试集调参和指标量化误差、结果不可追溯。

问题台账共 28 项：严重（S1）8 项，主要（S2）14 项，一般（S3）6 项。应先修复 S1-02～S1-06，再继续阶段 04；否则后续 PSF 估计会建立在错误的长度标签和失效的过渡区统计量上。

严重度定义：

- S1：阻断核心结论、造成错误实验标签，或使论文结论无效。
- S2：显著影响正确性、复现性、泛化性或交付完整性。
- S3：工程质量、维护性或表述准确性问题。

## 2. 严重问题（S1）

### S1-01 核心研究阶段和论文交付物为空

`04_PSF估计`、`05_完整盲复原流程`、`06_实验与论文写作`及 `data\real_blur` 都是空目录。README 宣称的 `psf_estimation.py`、`blind_restoration.py`、对比实验、论文初稿均不存在。因此当前内容只覆盖前置教学实验，尚未实现盲复原，更没有证据支撑 README 第 43 行的“精度更高、收敛更稳定”。

### S1-02 运动模糊长度全部偏大 1 像素

`01_退化模型与评价指标\degradation_template.py:31` 使用：

```python
for i in range(-length // 2, length // 2 + 1):
```

Python 中 `-length // 2` 等价于 `(-length) // 2`。实测请求长度 3/5/10/15/20/25 时，水平 PSF 的支撑分别是 4/6/11/16/21/26 像素。所有合成图、参数敏感性实验和后续“已知真实长度”的标签均存在 1 像素系统误差。斜向核还会因坐标取整产生重复或非均匀采样。

建议明确长度定义（采样点数还是端点距离），使用对称端点和 `cv2.line(..., lineType=cv2.LINE_AA)` 或亚像素轨迹积分，并为奇偶长度、角度、质心、能量和支撑范围添加测试。

### S1-03 过渡区宽度算法既不符合文档定义，换算公式也不成立

知识点文档把宽度定义为边缘法线剖面的 10%–90% 或 20%–80% 距离；`transition_zone_template.py:54-75` 实际把“全图梯度大于全局最大梯度的固定比例”的所有像素混成一个二值掩码。两者不是同一统计量。

`transition_zone_template.py:80-114` 又用 `2 × 过渡区内距离变换均值`估计带宽。对理想等宽长条，带内像素到最近边界的平均距离约为带宽的四分之一，因此该公式渐近只返回约一半带宽，而不是带宽。复杂纹理中，不同边缘、交叉点和相邻过渡带还会互相影响。

建议沿检测到的强边缘法线逐条采样 ESF，做单调拟合后测 10%–90% 宽度；再对边缘样本用中位数和置信区间汇总。不要用全图二值带的距离变换替代法线剖面宽度。

### S1-04 核心假设在 2/3 现有图像上未复现，代码仍打印成功

对项目现有三张清晰图，按脚本的长度 5/10/15/20/25 和 `gradient_ratio=0.1` 复测：

| 图像 | 宽度是否严格递增 | 线性斜率 | R² |
|---|---:|---:|---:|
| building | 否 | 0.02374 | 0.6086 |
| forest | 否 | -0.00246 | 0.0844 |
| professors | 是 | 0.12517 | 0.9951 |

`transition_zone_template.py:247-256` 只拟合斜率，不计算任务要求的 R²，并且不判断斜率符号就无条件打印“斜率为正 = 模糊越重，过渡区越宽 ✓”。在 `forest` 上这会把失败实验报告成成功。应根据斜率、R²、置信区间和单调性条件输出通过/失败，并保留每张图的原始数据。

### S1-05 “TV 正则化反卷积”实际不是文档中的 TV 反卷积

`02_非盲反卷积\01_知识点.md:118-129` 定义的是联合优化：

`min ||h*f-g||² + λ TV(f)`。

但 `deconvolution_template.py:197-228` 实际先运行 30 次 RL，再调用 `denoise_tv_chambolle` 对 RL 结果做去噪。它没有联合优化数据保真项与 TV 项，因此不能作为独立的“TV 正则化反卷积”与维纳、RL 做同层级方法比较。函数名、表格标签和论文解释都会误导。

可选择：把方法明确改名为“RL + TV 后处理”；或实现真正的 TV 反卷积（例如 ADMM、Chambolle–Pock 或经过验证的库函数），并验证目标函数和收敛性。

### S1-06 超参数调优使用测试图 Ground Truth，且在已四舍五入的指标上搜索

`tune_k.py`、`tune_k_precise.py` 和 `tune_tv.py` 直接在最终三张测试图上用 GT 选择最优参数，随后又在同一数据上报告性能，属于 oracle 调参/测试集泄漏。

更严重的是 `evaluate_restoration()` 在 `metrics_template.py:143-146` 先把 PSNR 四舍五入到两位；`tune_k_precise.py:44-68` 再用这些两位小数选择最优 K，却用 `.4f` 打印成四位精度。相同两位值会被 `argmax` 任意选中第一个，所谓“精细搜索”没有声明的精度。

建议指标函数返回原始浮点值，只在展示层格式化；按图像划分训练/验证/测试，验证集选全局参数，测试集只评一次。若要展示每图 oracle 上限，必须明确标为 oracle，不得作为方法性能。

### S1-07 实验结果不可追溯且会被固定文件名覆盖

脚本将结果写到固定目录和固定文件名，没有运行 ID、配置快照、时间戳、随机种子或防覆盖机制。审查期间检测到源目录存在并发运行/修改：`results\03_边缘检测` 从审查开始时的 50 张图变为 8 张过渡区图，原有边缘检测图不再存在。这不归因于某个确定操作者，但证明当前结果目录无法作为稳定实验记录。

建议每次运行创建独立目录，如 `runs/<timestamp>-<config-hash>/`，保存配置、环境、Git 提交、指标 CSV 和日志；最终汇总结果只从不可变运行目录读取。

### S1-08 “创新点更准、更稳定”的结论没有基线或文献证据

README 第 43 行直接宣称只从过渡区估计 PSF“精度更高、收敛更稳定”，但 PSF 估计代码为空，项目没有基线方法、消融、重复实验、统计检验、真实模糊数据或参考文献。并且当前过渡区量度已在 2/3 图像上失败。该句目前只能作为待验证假设，不能作为创新结论。

## 3. 主要问题（S2）

### S2-01 运行路径依赖当前工作目录

各脚本普遍使用 `../data`、`../results`。从阶段子目录运行时成立；从项目根目录按常见命令运行时会解析到 `J:\phd\data`，该目录不存在。PyCharm 临时配置为部分脚本设置了正确工作目录，但命令行、其他 IDE、测试和导入均不稳健。

应以 `Path(__file__).resolve()` 建立项目根路径，并把数据/输出路径作为参数。注意：当前环境的 `cv2.imread()` 对含中文的绝对路径实测返回 `None`，所以改为绝对路径时还需用 `np.fromfile + cv2.imdecode`（写图对应 `cv2.imencode + tofile`）。相对 ASCII 路径从阶段目录运行时实测可读。

### S2-02 评价协议不适合论文复原实验

合成模糊图和复原结果都保存为有损 JPEG，再重新读取计算 PSNR/SSIM，压缩误差混入退化与复原误差。指标还包含反射边界区域，没有声明裁边策略。建议合成数据和中间结果使用 PNG/TIFF，无损保存；按统一协议裁掉与核半径相关的边界，并同时报告 RGB/Y 通道约定。

### S2-03 手写 SSIM 与标准实现存在可见偏差

对三张 motion 图，手写 SSIM 相对 `skimage.metrics.structural_similarity` 的差值为 +0.00418、-0.01712、+0.00957。主要差异来自边界处理、窗口有效区和实现约定。用于教学可以保留，但论文表格应使用锁定版本的标准实现或严格对齐标准，并做回归测试。

### S2-04 指标 API 会掩盖数学和输入错误

`compute_psnr()` 对相同图返回 100，而非 `inf`；`compute_ssim()` 把数据范围固定为 255；函数未检查尺寸、通道、dtype、NaN 或范围。知识点称 SSIM 范围为 `[0,1]`，但标准 SSIM 可为负。建议显式传入/推断 `data_range`，验证形状与数值范围，保留原始精度，并把显示上限和真实数学值分开。

### S2-05 数据规模和任务说明不一致

实际只有 3 张清晰图；第二阶段任务第 78 行写“4 张清晰图 × 3 × 3 = 36 组”，按现有数据应是 27 组。3 张自然图不足以支持泛化或论文结论，且 `real_blur` 为空。需要公开基准数据集、训练/验证/测试划分和足量真实模糊样本。

### S2-06 数据来源、许可和伦理信息缺失

三张清晰图没有来源 URL、作者、许可、下载日期或内容使用说明；项目根也没有 LICENSE。含人物的 `professors.jpg` 用于论文时尤其要确认许可/隐私。应创建数据卡和逐文件来源清单，避免无法投稿或无法公开代码数据。

### S2-07 实验交付不完整

当前 `results\02_非盲反卷积` 只有 4 张单图测试结果，没有完整 27 组批处理结果、CSV 表或参数曲线。阶段 03 只保存图，宽度、梯度、斜率和 R² 只打印到终端；任务要求的阈值敏感性、散点图、R² 和阶段总结不存在。

### S2-08 过渡区阈值对图像内容和异常强边缘高度敏感

阈值定义为 `max_gradient * ratio`。单个高对比边缘、反光或噪点就会改变整图阈值；不同图的动态范围也不可比。`forest` 的负斜率实测已显示这一问题。建议使用局部边缘对比归一化、分位数/稳健阈值，并按边缘法线单独估计。

### S2-09 Laplacian 零交叉实现会产生大量伪边缘

知识点说通常先做高斯平滑（LoG），代码 `edge_detection_template.py:115-153` 却直接对原图做 Laplacian，只看符号变化，没有最小幅值阈值；还把跨越零点的两侧像素都标白，边缘会偏厚。应平滑、设置跨零幅度阈值，并明确 4/8 邻域和单像素定位规则。

### S2-10 Sobel 每图独立归一化，不能比较边缘强度

`edge_detection_template.py:63-69` 用每张图自己的最大梯度缩放到 255。模糊图即使绝对梯度显著下降，显示结果仍会被拉满；清晰/模糊之间不能定量比较。用于可视化时需注明；用于比较时保留原始梯度或使用固定标度。

### S2-11 理论文档有关键错误或过度表述

- `02_非盲反卷积\01_知识点.md:21` 称已知 PSF 的非盲反卷积“适定，有唯一解”；已知 PSF 仍常因零频响应和噪声而病态，后文第 28–31 行其实也承认这一点。
- `03_边缘与过渡区提取\01_知识点.md:206-208` 把自然图中运动模糊宽度直接等同运动长度；实际只对理想阶跃且取决于运动方向在边缘法线上的投影。
- 散焦圆盘与阶跃卷积不是高斯误差函数；误差函数对应高斯 PSF。
- “Canny 是目前最好的通用方法”“过渡区方案更准更稳”等均需限定或引用。

### S2-12 缺少可复现环境

根目录没有 `requirements.txt`、`environment.yml`、`pyproject.toml` 或锁文件。环境说明记录的是某台机器的绝对 Conda 路径和显卡。当前实测 Python 3.11.15、NumPy 2.4.6、OpenCV 5.0.0、scikit-image 0.26.0，但其他机器无法据此可靠重建。

### S2-13 调试/调参脚本导入即执行且缺少错误检查

`debug_tv.py`、`tune_k.py`、`tune_k_precise.py`、`tune_tv.py` 的主体不在 `if __name__ == '__main__':` 下，导入模块就会读图并开始计算。多个脚本硬编码 `building.jpg`，读图失败后直接把 `None` 传入指标函数。应函数化、参数化，并统一做文件存在性和图像解码检查。

### S2-14 没有自动化测试和实验断言

项目没有测试目录。当前这些错误本可由很小的测试捕获：PSF 和为 1、支撑长度等于标签、质心居中、相同图 PSNR、SSIM 对齐标准库、反卷积输出尺寸、核心趋势不满足时失败而非打印勾。建议先建立 `pytest` 基线，再进入 PSF 估计阶段。

## 4. 一般问题（S3）

### S3-01 随机噪声不可复现

`add_gaussian_noise()` 使用全局 `np.random`，没有 seed/RNG 参数；生成的 noisy 图无法由配置独立复现。应传入 `numpy.random.Generator` 并保存 seed。

### S3-02 进度标记和实际状态不一致

三个实验任务文档共有 48 个未勾选项；代码中的 TODO 多数已填写却仍保留模板提示；没有任何 `阶段总结.md`。README 期望的文件名是 `degradation.py`、`metrics.py` 等，实际仍为 `_template.py`。这会让完成度无法判断。

### S3-03 输出写入失败可能被静默忽略

`imwrite_unicode()` 返回布尔值，但调用方不检查；函数也不负责创建父目录。编码或写入失败时实验仍可能打印“已保存”。应在失败时抛异常并记录绝对输出路径。

### S3-04 参数校验不足

PSF 函数没有验证核大小为正奇数、半径/长度不越界、sigma 为正；极端参数可得到空核并在归一化时产生 NaN。指标和复原函数也没有验证图像/PSF 形状、PSF 非负与和为 1。

### S3-05 项目文件卫生较差

根目录没有 `.gitignore`，却包含 `.idea`、用户级 `workspace.xml` 和多个 `.pyc`。源代码、生成数据和结果混在一起。建议忽略 IDE/缓存/运行输出，只版本化小型可追溯样例和配置。

### S3-06 重复代码与包结构不稳健

多个文件复制 `imwrite_unicode()`，并用 `sys.path.append()` 导入上级目录；`deconvolution_template.py` 还重复追加同一路径。`process_one_image(img_path, clean_dir)` 的 `clean_dir` 参数未使用。建议建立可安装包和共享 I/O/路径/指标模块。

## 5. 修复顺序

1. 冻结现有结果：建立不可变 run 目录和配置/环境记录，避免继续覆盖证据。
2. 修正 PSF 长度语义并重生成全部 synthetic blur；旧图标记为无效，不与新结果混用。
3. 重写过渡区宽度为边缘法线 ESF 的 10%–90% 测量，添加合成阶跃单元测试。
4. 让趋势验证真正检查斜率、R²、置信区间和跨图稳定性；失败就停止进入 PSF 估计。
5. 将当前方法改名为 RL+TV，或实现真正 TV 反卷积；修复指标原始精度和数据划分。
6. 统一文件相对路径、中文路径 I/O、无损图像格式、环境锁文件和测试。
7. 扩充公开合成/真实数据、基线、消融和统计检验后，再陈述创新与论文结论。
