# P21：首轮原生整图开发评价与推理效率协议

登记日期：2026-09-06。此协议在读取本轮整图质量结果、执行资源探测和计时前固定。

## 1. 范围与权重选择

- 首轮只使用最早的固定微调种子 3407，不按整图效果挑选种子。
- 三组分别为 P12A_local_control_v0（Local）、P12G_uniform_scale_adaptive_gate_v0（C00）、P16C01_teacher_only_seed3407_v0（C01）。
- 使用各组既有 256 中心裁剪开发 PSNR 选出的 best.pt，三者恰好均为 step 3000；不使用整图结果重新选择权重。
- 复用同一 GoPro 官方 train 内部 385 张冻结开发图，录像组 GOPR0372_07=175、GOPR0378_13=110、GOPR0385_11=100。没有加载官方 test。
- 本轮不训练、不改模型、不调参、不新增 TMT 或公共模型实验。仅完成首种子的整图可行性和描述性效果检查，不能标为三种子整图复现。

## 2. 原生整图和资源检查

模型输入为原始 RGB 全图、[0,1]、batch=1、CUDA autocast float16、eval、关闭梯度。不缩放、不裁剪、不分块、不做 TTA 或自集成，不修改已有归一化、采样网格和卷积实现。

保留主干现有的右侧/底部 reflect padding 到 4 倍数及输出裁回原尺寸。PSNR 评价原图完整像素，不额外裁去边缘。SSIM 保留原 skimage 默认窗口及其内部边界统计方式。

先检查全部 385 对图像的文件头尺寸，并记录输入/目标文件指纹。每个录像组按图像名排序取中间帧（零基索引 n//2），共 3 张。预检三种模型在这些原生尺寸的输出形状、有限性及显存；不读取清晰图像像素计算质量。

如出现 OOM、非有限输出、尺寸/名单不符，停止本轮并保存失败记录。不得悄悄缩放或改用分块继续报原生整图成绩；若需要分块，另行登记协议。GroupNorm(1,C) 的空间统计会受输入区域影响，因此分块与整图并不保证等价。

固定三帧资源探测要求全部 385 张原生尺寸为 720×1280（高×宽）；若不符合，先停止并记录尺寸分布，另行登记覆盖全部尺寸的资源探测。预检通过临时 hook 记录 key_value 输出 dtype，随后移除；当前采样网格沿用其 dtype，半精度坐标的整图量化误差列为实现局限，本轮不改代码。

## 3. 质量评价和分组

- 逐图 RGB PSNR：先把输出和目标转 float32 并 clamp 到 [0,1]，计算所有通道/像素的 MSE，再转 −10 log10；MSE 下界 1e−12。
- SSIM：沿用训练评价器的 skimage structural_similarity，data_range=1、channel_axis=2，其他选项不变。保存库版本。
- 总体指标是逐图指标的等权平均，不是先汇总所有 MSE 再转 PSNR。
- 每张图保存 input/Local/C00/C01 的完整图像 PSNR、SSIM、尺寸和匹配差值；保存全部三个录像组和代理档，不筛除负结果。
- 主要代理分组沿用 P20 中同一图的中心裁剪标签（96 重/106 中/183 轻），便于固定名单比较；明确命名为 crop-defined proxy strata。另记录整图 input PSNR 及套用原阈值的描述性标签，不声称阈值已在整图分布重新校准。
- 中心裁剪指标仅作为另一个评价区域的历史参照，不与整图指标直接相减后称为方法提升。

预定阶段判断：整图总体 C01−Local 与 C01−C00 均要求 PSNR>0、SSIM≥0，称为总体方向延续检查。分组结果全部报告，不临时添加或调整分组通过阈值。未通过则如实定位，不立即调参或改选种子补救。

该符号检查不是早期 +0.15 dB 目标，不是统计显著性，也不替代 P20 的裁剪开发筛选线。只有一个整图种子，不计算虚假的跨种子标准差。

## 4. 推理计时与显存口径

使用资源预检固定的 3 张模糊整图。输入预先驻留 GPU，模型预先加载；计时不包含磁盘读取、CPU 解码、H2D/D2H、PSNR/SSIM、权重加载和输出保存。

三张图分别为三轮，三组执行顺序依次轮转：

1. Local → C00 → C01；
2. C00 → C01 → Local；
3. C01 → Local → C00。

每个“图像×模型”独立运行，GPU 同时只保留该组模型和该张输入；先清理上一组 Python 引用与缓存，再加载。10 次预热、30 次正式 forward，记录全部 90 次/模型的原始计时；不挑最快记录。

CUDA events 记录同一流上从 forward 前到 forward 后的间隔（可能包含主机提交间隙，不声称纯内核执行时间）。每次测量同步后完成；同时记录包含 Python 调用与同步开销的 host wall latency。汇总每帧和合并样本的均值、中位数、p95。该指标是 batch1 热态模型延迟，不是端到端应用帧率或批量吞吐率。

预热后、正式测量前记录 memory_allocated/reserved，并 reset_peak_memory_stats；报告绝对峰值 allocated/reserved，以及 allocated 峰值减去模型+输入常驻基线的增量。它们是 PyTorch 分配器指标，不等于 nvidia-smi 中整个桌面的显存。首调用资源预检另存，不混入热态计时。

保持与旧评价一致的 cudnn.benchmark=False、cudnn.deterministic=True；不额外启用编译/融合、改变 TF32 标志或自动寻找最优后端。保存实际 PyTorch/CUDA/cuDNN/skimage 版本、GPU 型号、TF32 状态、各计时块前后 nvidia-smi 状态。若有并发负载，披露计时可能受影响。

不预设必须更快或更省显存。Top-K 前仍形成稠密候选张量，参数增加约 2.9% 不代表计算或显存只增加 2.9%。C00/C01 推理图相同，轻微耗时差异不解释为监督改变了计算复杂度。
